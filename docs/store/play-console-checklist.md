# Nearo 2.0 Play Console 출시 체크리스트 (#37, #38)

Play Console에서 사용자가 직접 하는 일을 순서대로 적었습니다. 앱은 기존 앱 `com.gamenuri.btscanner24`의 업데이트입니다. 새 앱을 만들지 않습니다.
붙여 넣을 문구는 `docs/store/listing.md`, 데이터 보안 답안은 `docs/store/data-safety.md`, 빌드 방법은 `docs/RELEASE.md`에 있습니다.

## 0. 올리기 전에 준비할 것

- [ ] 기존 앱을 서명한 키스토어 파일과 별칭, 비밀번호 (인증서: O=gamenuri, OU=lab, C=KR). 비밀번호는 PC의 `local.properties`에만 적고 채팅이나 git에 올리지 않습니다.
- [ ] 실제 AdMob 앱 ID와 광고 단위 ID 3개(배너, 전면, 보상형). 역시 `local.properties`에만.
- [ ] 개인정보처리방침에 넣을 개발자 이름, 문의 이메일, 시행일.
- [ ] `develop` → `main` PR 머지, A50에서 릴리스 빌드 확인.
- [ ] 스토어 스크린샷(언어별)과 피처 그래픽 1024×500, 아이콘 512×512.

## 1. 같은 키로 서명

- [ ] Play Console > 설정 > 앱 서명에서 "Play 앱 서명" 사용 여부를 확인합니다.
  - 사용 중이면: 업로드 키 인증서의 SHA-1이 PC의 키스토어와 같은지 확인합니다.
  - 사용 중이 아니면: 기존 앱을 서명한 바로 그 키로 서명해야 합니다. 다른 키로는 업데이트를 올릴 수 없습니다.
- [ ] PC에서 `keytool -list -v -keystore <키스토어 경로>`로 SHA-1을 확인해 Console의 값과 비교합니다.
- [ ] 키를 찾지 못하면 여기서 멈추고 알려 주세요. Play 앱 서명을 쓰는 경우에만 업로드 키 재설정을 요청할 수 있습니다.

## 2. 버전

- [ ] 지금 스토어에 올라가 있는 버전의 버전 코드를 확인합니다 (프로덕션 > 출시 내역).
- [ ] 새 빌드는 버전 코드 2, 버전 이름 2.0.0입니다. 스토어의 기존 코드가 2 이상이면 올리기 전에 알려 주세요. `app/build.gradle.kts`의 `versionCode`를 그보다 크게 올려야 합니다.
- [ ] 패키지 이름이 `com.gamenuri.btscanner24`인지 확인합니다 (바꾸지 않습니다).

## 3. 앱 이름과 스토어 등록정보

- [ ] 성장 > 스토어 등록정보 > 기본 스토어 등록정보에서 앱 이름을 `Nearo: Bluetooth Finder`로 바꿉니다. 이것은 영어(기본) 이름이고, 다른 언어는 `listing.md` 맨 위의 언어별 이름을 씁니다 (예: 한국어 `Nearo: 블루투스 기기 찾기`).
- [ ] 번역 추가: 한국어, 일본어, 독일어, 프랑스어, 스페인어(스페인, 중남미), 포르투갈어(브라질).
- [ ] 언어마다 `listing.md`의 간단한 설명(80자)과 자세한 설명을 붙여 넣습니다.
  - `[153]` 줄은 이어폰 큰 소리 기능이 빌드에 들어갔을 때만 넣습니다.
  - `[79]` 줄은 트래커 알림이 들어갔을 때만 넣습니다.
  - 붙여 넣을 때 `[153]`, `[79]` 표시는 지웁니다.
- [ ] 언어마다 스크린샷, 피처 그래픽, 아이콘을 올립니다.
- [ ] 카테고리는 도구(Tools)를 유지합니다. 문의 이메일을 확인합니다.

## 4. 앱 콘텐츠 (정책 > 앱 콘텐츠)

- [ ] 개인정보처리방침 URL: `https://kywood.github.io/findBT/privacy/` (페이지가 실제로 열리는지 먼저 확인).
- [ ] 광고: "예, 광고가 포함되어 있습니다".
- [ ] 광고 ID: "예", 용도는 광고.
- [ ] 데이터 보안: `data-safety.md`대로 답합니다. 요점은 다음과 같습니다.
  - 수집·공유하는 것은 광고 SDK가 보내는 것뿐입니다: 대략적인 위치(IP 기반), 앱 상호작용, 진단, 기기 ID.
  - 스캔 결과, 저장한 기기, 마지막 위치, 트래커 기록은 휴대폰 안에만 있으므로 "수집 안 함"입니다.
  - 정확한 위치는 "수집 안 함"입니다.
  - 전송 중 암호화 "예", 계정 없음.
- [ ] 포그라운드 서비스 권한 신고: 유형 "연결된 기기"와 "위치". 설명은 "사용자가 켠 보호 모드에서 내 블루투스 기기가 감지되지 않으면 알려 주고, 마지막으로 감지된 대략적인 장소를 기록한다". 보호 모드를 켜고 알림이 뜨는 짧은 영상 링크가 필요합니다.
- [ ] 위치 권한: 백그라운드 위치는 쓰지 않습니다. 관련 질문이 나오면 "아니요"입니다.
- [ ] 콘텐츠 등급 설문과 타겟 연령(13세 이상, 어린이 대상 아님)을 다시 확인합니다.
- [ ] 앱 액세스: 로그인 없음, "모든 기능을 제한 없이 사용 가능".

## 5. 비공개 테스트 (#37)

- [ ] 테스트 > 비공개 테스트에서 트랙을 만들고 `app-release.aab`를 올립니다.
- [ ] 출시 노트는 `listing.md`의 "What's new"를 언어별로 붙여 넣습니다.
- [ ] 테스터 이메일 목록을 추가하고 참여 링크를 보냅니다.
- [ ] 1~2주 동안 확인: 비정상 종료 없는 사용자 99% 이상, ANR, 찾기 성공 여부에 대한 테스터 의견.
- [ ] 구매 테스트: 라이선스 테스터 계정으로 프리미엄 구매와 복원, 보상형 광고 1회.

## 6. 프로덕션 단계적 출시 (#38)

- [ ] 프로덕션 > 새 버전 만들기 > 비공개 테스트에서 확인한 같은 번들을 승격합니다.
- [ ] 국가/지역: 기존 배포 국가를 유지하고, 전 세계 출시가 목표이므로 빠진 국가가 있으면 추가합니다.
- [ ] 출시 비율을 20%로 설정하고 검토에 제출합니다.
- [ ] 20%에서 2~3일 지켜봅니다: 비정상 종료 없는 사용자 99% 이상, 별점과 리뷰, 권한 관련 정책 경고.
- [ ] 문제가 없으면 50%, 100% 순서로 올립니다. 문제가 있으면 "출시 중단"을 누르고 알려 주세요.
- [ ] 출시 후 4주 동안 KPI(설치, 유지, 찾기 성공, 광고 수익)를 보고 목표를 조정합니다.

## 아직 확인되지 않은 것

- 릴리스 빌드를 실제 폰에서 실행한 적이 없습니다.
- Android 12 이상에서의 동작과 트래커 감지 패턴은 실기기로 확인되지 않았습니다.
- 번역은 원어민 검수를 받지 않았습니다.
